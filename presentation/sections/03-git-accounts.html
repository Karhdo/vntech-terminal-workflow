Multiple git accounts

One global identity means work commits with a personal email, pushes with the wrong SSH key, and gh as the wrong user. Fix: let the directory choose.

includeIf

The directory decides who you are: includeIf loads a different identity per folder

~/.gitconfig (in the dotfiles repo)
[includeIf "gitdir:~/Workplace/Karhdo/"]
  path = ~/.gitconfig-karhdo
[includeIf "gitdir:~/Workplace/Spartan/"]
  path = ~/.gitconfig-spartan
~/.gitconfig-spartan
[user]
  name = Spartan - Khanh Do
  email = <work email>
  signingkey = ~/.ssh/spartan.pub
[alias]
  spartan-check = !echo '✅ Spartan config loaded!'
same command, two folders
❯ cd ~/Workplace/Karhdo/dotfiles
❯ git config user.name
Karhdo
❯ cd ~/Workplace/Spartan/loanbud-hq
❯ git config user.name
Spartan - Khanh Do
❯ git spartan-check
✅ Spartan config loaded!
  • The trailing / in gitdir: matches every repo under that folder.
  • The *-check alias exists in only one include file, so it shows which one loaded.
  • signingkey comes from the same file: with gpg.format = ssh and commit.gpgsign = true, every commit is signed with that account's SSH key.

SSH host aliases

Two host aliases for github.com, each tied to one key

~/.ssh/config (not in the repo)
# Karhdo's GitHub
Host github
  HostName github.com
  User git
  IdentityFile ~/.ssh/karhdo
  IdentitiesOnly yes

# Spartan's GitHub
Host github-spartan
  HostName github.com
  User git
  IdentityFile ~/.ssh/spartan
  IdentitiesOnly yes
the remote URL picks the alias
git@github:Karhdo/dotfiles.git
git@github-spartan:spartan-trucle/vntech-load-balancer.git
  • Both aliases reach the same github.com. Only the key differs.
  • IdentitiesOnly yes stops ssh-agent from offering the other key first.
  • Clone with the alias: git clone git@github-spartan:org/repo.git. A URL copied from GitHub says github.com, so change that part.

gh + direnv

direnv gives the gh CLI a different token in each workspace

# ~/Workplace/Spartan/.envrc (never committed)
export GH_TOKEN=github_pat_…

# once per workspace
direnv allow ~/Workplace/Spartan

# .zshrc
eval "$(direnv hook zsh)"
export DIRENV_LOG_FORMAT=""   # no "loading .envrc" noise
  • Entering the folder exports the variables, and leaving it unsets them.
  • gh prefers GH_TOKEN over its saved login, so the folder decides the account.
  • Fine-grained token, scopes repo, read:org, gist. Each workspace has its own, so revoking one doesn't touch the other.
