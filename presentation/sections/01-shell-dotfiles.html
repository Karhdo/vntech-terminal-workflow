.zshrc

Your terminal runs one script every time it opens

  • zsh is the default shell on macOS since Catalina (10.15).
  • Every new tab or pane starts an interactive zsh, which runs ~/.zshrc line by line.
  • Aliases, PATH, prompt, plugins, key bindings: anything that "just works" when you open a terminal comes from this file.
  • Only after the last line do you get a prompt. A slow line here makes every new tab slow.

Managing .zshrc

Group .zshrc by tool, and comment why a line is there

# -------------------- Plugins --------------------
source ~/.zsh_custom/zsh-autosuggestions/zsh-autosuggestions.zsh
# -------------------- Starship Prompt --------------------
eval "$(starship init zsh)"
# -------------------- FZF --------------------
export FZF_DEFAULT_COMMAND="fd --type f --hidden --follow --exclude .git"
# -------------------- Aliases --------------------
alias rz="source ~/.zshrc"
# -------------------- PATH --------------------
export PATH="$HOME/.local/bin:$PATH"
# -------------------- Tools Init --------------------
eval "$(zoxide init zsh)"
# -------------------- Docker --------------------
# Testcontainers ignores Docker contexts and reads DOCKER_HOST
export DOCKER_HOST="unix://$HOME/.colima/default/docker.sock"
  • One block per tool. Removing a tool means deleting one block.
  • Order matters: a block that runs a command needs that command on PATH first, so Homebrew goes near the top.
  • Comment the why, not the what. Six months later, "Testcontainers ignores Docker contexts" is the line you need.
  • cz opens it inside the dotfiles repo, rz (source ~/.zshrc) applies it. source never removes an old alias: exec zsh for a clean reload.

Dotfiles

Config in $HOME has no history and no backup, so move it into a repo that mirrors $HOME

~/Workplace/Karhdo/dotfiles (git repo)
dotfiles/
├── .zshrc
├── .tmux.conf
├── .wezterm.lua
├── .gitconfig  .gitconfig-spartan
├── .config/
│   ├── starship.toml
│   ├── tmux/claude-popup.sh …
│   └── lazygit/  nvim/  bat/
├── Brewfile
└── README.md   # repo-only: never linked
ls -la ~
.zshrc       -> Workplace/Karhdo/dotfiles/.zshrc
.tmux.conf   -> Workplace/Karhdo/dotfiles/.tmux.conf
.wezterm.lua -> Workplace/Karhdo/dotfiles/.wezterm.lua
.gitconfig   -> Workplace/Karhdo/dotfiles/.gitconfig
.config      -> Workplace/Karhdo/dotfiles/.config
  • The files in $HOME are symlinks into the repo.
  • Editing ~/.zshrc edits the repo file. git commit is the backup, and git log shows what you changed last week.

GNU Stow

Stow creates the symlinks, so you never type ln -s

# from the repo root, link everything into $HOME
cd ~/Workplace/Karhdo/dotfiles
stow -t ~ .

# after adding a new top-level file
stow -R -t ~ .

# .stow-local-ignore: stays in the repo only
README.md  CLAUDE.md  Brewfile  images  .git
  • Stow mirrors the repo's paths: dotfiles/.tmux.conf becomes ~/.tmux.conf.
  • It refuses to overwrite a real file. Move the old one away first.
  • Folding: if ~/.config doesn't exist yet, Stow links the whole directory. Then every app that writes to ~/.config writes into your repo.
gotchaThat is how gh tokens and Copilot auth ended up inside my repo folder. .gitignore keeps them out of git (# Secrets — DO NOT TRACK). stow --no-folding avoids it: only files get linked, never directories.

Brewfile

One file lists every tool, and one command installs them

# --- Core CLI ---
brew "stow"        # symlink manager for these dotfiles
brew "tmux"        # terminal multiplexer
brew "starship"    # shell prompt
# --- Shell tooling (.zshrc) ---
brew "fzf"         # fuzzy finder
brew "fd"          # fast find, backs fzf
brew "zoxide"      # smarter cd
brew "eza"         # ls replacement
brew "direnv"      # per-directory env (GH_TOKEN)
# --- Containers ---
brew "colima"      # VM running the Docker engine
# --- Casks ---
cask "wezterm"
cask "font-hack-nerd-font"
❯ brew bundle
Using stow … Installing lazydocker
Homebrew Bundle complete!
  • A comment per line says why the tool is there.
  • Installed something by hand? Add it here, or the next laptop won't have it.
  • New Mac: install Homebrew, clone, brew bundle, stow -t ~ .. The README lists all ten steps.
