tmux

tmux keeps your sessions running after the terminal window closes

  • Session: one per project. Window (numbered): like a tab. Pane: a split inside a window.
  • Close WezTerm, or let it crash, and the server keeps every shell and process running.
  • prefix d detaches. tmux attach -t LoanBud brings it back exactly as it was.
  • The Claude popups in this part are tmux sessions too. That is why they survive being closed.

.tmux.conf

One prefix for everything, and vim keys to move between panes

# prefix: Ctrl-t instead of Ctrl-b
unbind C-b
set-option -g prefix C-t

# move between panes: h j k l (repeatable)
bind -r h select-pane -L
bind -r j select-pane -D
bind -r k select-pane -U
bind -r l select-pane -R
# resize by 5 cells
bind -r C-h resize-pane -L 5

setw -g mouse on
set -g history-limit 10000
set -g renumber-windows on          # 0 2 5 → 0 1 2
# pass 24-bit color through to WezTerm
set -as terminal-features ',xterm-256color:RGB'
bind r source-file ~/.tmux.conf
C-t c
New window
C-t % / "
Split side by side / top and bottom
C-t h j k l
Move to the pane left / down / up / right
C-t n / p
Next / previous window
C-t s
Switch session from a list
C-t d
Detach: everything keeps running
C-t r
Reload .tmux.conf
why C-tCtrl-b is a long stretch on the keyboard and also moves the cursor back in the shell. Pick a prefix you can press with one hand.

tmux-claude-hatch

Claude runs in a tmux popup, one keypress away, and keeps working while it's hidden

set -g @plugin 'craftzdog/tmux-claude-hatch'
# every popup Claude starts without permission prompts
set -g @claude_args '--dangerously-skip-permissions'
# wrapper: drop to a shell when Claude exits
set -g @claude_command "$HOME/.config/tmux/claude.sh"
# picker enter: open the chosen Claude here
set -g @claude_fzf_options \
  "--bind 'enter:become($HOME/.config/tmux/claude-pick.sh {})'"

run '~/.tmux/plugins/tpm/tpm'

# AFTER tpm, to override the plugin's own y
bind-key y run-shell "$HOME/.config/tmux/claude-popup.sh \
  '#{q:session_path}' '#{q:pane_current_path}' '#{q:window_id}'"
bind-key Y run-shell "… --resume"
C-t y
Open Claude for the current directory
C-t Y
Same, starting with --resume
C-t u
Picker: every Claude, waiting / working
C-t d
Hide it; Claude keeps working
  • Each popup is a nested tmux session, so hiding it only detaches.
  • claude.sh drops to a shell when Claude exits: CtrlC never kills the popup.

Claude Code settings

Claude Code knows it runs inside tmux

// ~/.claude/settings.json (excerpt, not in the repo)
{
  "teammateMode": "tmux",
  "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" },
  "tui": "fullscreen",
  "theme": "custom:tokyo-night",
  "effortLevel": "high",
  "enabledPlugins": {
    "typescript-lsp@claude-plugins-official": true,
    "pyright-lsp@claude-plugins-official": true,
    "jdtls-lsp@claude-plugins-official": true,
    "tmux-claude-hatch@tmux-claude-hatch": true
  },
  "skipDangerousModePermissionPrompt": true
}
  • Agent teams in tmux: when Claude starts teammates, each one opens in its own tmux pane, so you can watch them work.
  • Same theme as the terminal, tmux and bat.
  • LSP plugins give Claude go-to-definition and diagnostics in TS, Python and Java.
  • --dangerously-skip-permissions (from .tmux.conf) lets a hidden Claude keep working. Fine on a personal laptop with every project in git; never with prod credentials in the shell.
